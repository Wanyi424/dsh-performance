# 设计说明

0.2.0 由后端开发完成，没有经过产品和设计评审。0.3.0 从用户要回答的问题出发重做了信息结构。0.4.0 根据实际使用的反馈做了两件事：一是三项指标同屏、不再切换；二是补上整机参照、交互延迟、进程趋势和工具进程启停。0.5.0 加入按插件拆分后台；0.6.0 把它从「点按钮分析」改为随每次读数持续统计。

0.7.0 是一次产品和交互评审后的重做：先给结论，再给证据，细节放进抽屉。页面回答「有没有问题、是谁」，抽屉回答「它怎么了」。中途试过左右分栏、在右栏里原地切换详情的方案，实际使用比原来的抽屉更差，已放弃，原因记在下面。视觉沿用翻译和 Markdown 笔记的原生风格：界面颜色只取 DSH 主题变量，52px 顶栏，卡片 12px 圆角。装进 DSH 试用后又收了一轮：轨道左栏每条只留一个数和一行对照；「谁在占用」改为按列排，后台里分出「插件」和「不属于插件」，插件不再折叠第二层。原因同样记在下面。

## 用户要回答的问题

| 问题 | 页面里的回答 |
| --- | --- |
| 电脑慢，是不是 DSH 造成的？ | 顶部结论直接说；如果主要是别的程序，也会说「电脑很忙，但主要不是 DSH」。CPU 和内存轨道旁各有一行「整机」，对照 DSH 和整台电脑 |
| 是哪一部分、哪个程序在占用？ | 「谁在占用」一张表：各部分、插件、DSH 启动的程序；结论里直接点名占用最多的那个，「查看原因」打开它 |
| 刚才卡的那一下和什么同时发生？ | 三条轨道共用时间轴，一根竖线贯穿全部；程序启停画在最下方，可以点开 |
| 长时间运行后内存有没有涨？ | 看内存轨道的走势；半小时涨过 300 MB 时结论点名涨得最多的部分 |
| 哪个插件在占用后台？ | 「后台」在表里默认展开为各插件、「DSH 自身」和「其他」；插件的详情里有最耗时的函数和占内存的位置 |
| 怎么把情况告诉别人？ | 「复制诊断报告」，只列程序名，不含命令行和路径 |

## 设计原则

1. **先结论，后证据，再细节**：结论、趋势、表格在页面上，其余都在抽屉里。
2. **一个数字只出现在一个地方**：DSH 的当前 CPU 和内存只在轨道旁；各部分的平均值只在表里；正常时的结论不重复数字；峰值和变化量在图上一眼可见，轨道旁不再写。
3. **宽度留给时间**：趋势图永远占满宽度。
4. **点开不离开**：详情浮在页面上，关掉就回到原处，列表的位置和展开状态都还在。
5. **页面用日常用语，技术信息不藏但后置**：页面上是「界面」「后台」「启动的程序」；PID、命令行、函数名和路径在抽屉里。
6. **平静**：正常时页面不抢注意；有问题时只有结论变色，侧栏入口亮一个点。
7. **用排版和轻重代替删减和折叠**：信息显得乱时先理结构：每种信息一列、对齐、分组、分出主次，而不是删掉；不重要的行变浅、自然排到下面，而不是藏起来。

## 关键取舍

- **详情用侧边抽屉，而不是分栏**：
  - 左右分栏让趋势图少了三分之一宽度，右栏 340–420px 又放不下名称和两列数字，两边都挤。
  - 在右栏里原地切换详情，列表就被替换了：看完一个要「返回、找到、再点」，比较两个程序要来回好几次；详情也被压在窄栏里。
  - 抽屉宽 540px、整屏高，背后的页面不动。要逐个查看时用上下箭头（K / J）按列表顺序切换，不用关了再点；从「后台」点进插件这类下一层，左上角可以返回。
  - 抽屉只盖住本页，不盖 DSH 侧栏；背景加一层很淡的遮罩，抽屉打开时背后的页面不可操作，关闭后焦点回到打开它的那一行。
- **联动时间轴，而不是三张卡片切换**：对照同一时刻是诊断的核心。轨道共用横轴；纵轴各自独立（单位不同），从不把两个量画在同一纵轴上。每条轨道的当前值写在它左边，不另做指标卡。
- **轨道左栏每条固定三行**：名称、当前值、一行对照（CPU 和内存是整机，界面响应是最长的一次卡顿），三条读法相同。原先每条四五行，同一行位在不同轨道里放的东西不一样，还混着「此刻」和「这段时间」，只能逐字分辨，界面响应那条还超出了轨道高度。峰值和变化量看图，整机内存的 GB 数在指向「整机」时显示，操作响应看图上的圆点；「1 次卡顿」也按数字加单位排，中文不放大。
- **给结论，规则公开**：结论只按固定规则得出（`src/verdict.ts` 的 `RULES`），「判断依据」里逐条列出条件和级别。需要留意的情况先说；侧栏圆点只在「需要留意」时出现，「DSH 正在忙」这类只是告知。
- **插件放在「后台」下面，而不是单独一张表**：插件没有自己的进程，它们的 CPU 是后台的一部分。单独成表时两张表的数字不能相加；放在后台下面，CPU 几行相加正好是后台。默认展开并列出全部插件，因为「哪个插件在占用」是常见问题；用小标题分成「插件」和「不属于插件」两组，一眼分清哪些是插件。几乎不占用的行整行变浅、自然排在下面，不再折叠：展开后台还要再展开一次才能看全，多一层折叠只多一次点击，变浅已经说明「它不重要」。内存回收、其他代码和其余工作在表里合成一行「其他」，在详情里分开。插件的内存是抽样估算，和后台的进程内存口径不同，几行加起来不等于后台；表里不加「约」字，指向数字时说明。
- **列表按列排，而不是删减说明**：原版把说明叠在名称下面（一级行）或挤在名称后面（二级行），左边成了一堵字墙，数字却远在最右边，中间一大片空白。试过删掉说明，列表变得简陋，也分不清哪些是插件。现在每种信息一列：名称、CPU、内存、趋势、说明；数字紧跟名称，说明是次要信息，放在最后一列，富余的宽度留在行尾，不夹在名称和数字中间。也比较过说明放中间、数字靠右的常见排法，说明和数字之间仍留一段空白，没有采用。
- **插件归属常驻统计**：
  - **为什么常驻**：按需分析要用户先复现问题，也回答不了「刚才那一下是谁」。常驻后，插件和其他指标共用同一条时间轴和历史，结论也能据此点名。
  - **代价拆开处理**：Windows 实测，每 10 毫秒采样一次的常驻开销低于计量精度；真正的代价是两种停顿。启动分析器要扫描整个堆（150 MB 约 0.3 秒），所以只在后台启动时启动一次；读取内存前必定做一次完整的垃圾回收（约 0.1 秒），所以内存每 5 分钟读一次。
  - **可以暂停**：用 DevTools 调试后台时可能需要，开关在「后台」的详情里。
  - **口径**：CPU 用所选时间范围内的平均值，因为单次读数里大多数插件为零，逐次排序会来回跳；内存用最近一次读取的值，并写明读取时间。
  - **归属规则**：「调用栈上离样本最近的插件代码」，它决定了能回答什么：插件自己的代码和它同步调用的 DSH 代码。不能回答的写在「这些数字怎么来的」里：异步完成的工作、线程池里的读写、界面部分。
- **启停道只画在视图内开始或结束的程序**：整段都在运行的程序没有可标记的事件，它们在表里。
- **不做的指标**：
  - GPU 占用：PDH 每次要枚举数百个 GPU 引擎计数器，开销远超整套采集；
  - 网络流量：按进程统计需要管理员权限的系统跟踪；
  - 界面卡顿归因到插件：DSH 把各插件入口合并成一个脚本加载，React 渲染也统一记在 DSH 名下，归因不可靠；页面也没有开启浏览器的 JS 采样接口（需要 DSH 下发 `Document-Policy` 响应头）；
  - 界面 JS 内存：Chromium 默认只给取整、低频更新的值。

## 视觉规范

- **层次**：只有趋势和表格是卡片（1px 边线、12px 圆角）；结论正常时不加框，有问题时用状态色的淡底卡片；抽屉是唯一带阴影的元素。
- **字号**：抽屉标题 18，大数字 22（单位缩到 13），正文 13，说明 12，坐标 10.5。表格和坐标用等宽数字。
- **列表**：每行单行，一级 40px、二级 34px；列宽固定（名称 252、CPU 76、内存 92、趋势 120），说明占余下的宽度。一级行用色块对应图表颜色，名称和数字稍重；二级行不带标记，挂在父级色块下一条该色的细竖线上，分隔线从名称处开始，趋势小图只画线；后台下的小标题与二级行的名称对齐。说明用三级文字色，放不下时截断，指向名称可看全文。列头写明口径（「15 分钟平均」「当前」）。
- **配色**：五个组成部分使用一套经过校验的分类色，按堆叠顺序依次分配，浅色、深色主题各一套。校验在 DSH 实际的白色和 `#191c22` 背景上进行，相邻色在色盲模拟下 ΔE ≥ 8.4，正常视觉 ΔE ≥ 19。浅色主题下青、黄、洋红对背景的对比度低于 3:1，因此每个数值都能在提示框和表格中读到。

  | 组成部分 | 浅色 | 深色 |
  | --- | --- | --- |
  | 界面 | `#2a78d6` | `#3987e5` |
  | GPU | `#eb6834` | `#d95926` |
  | 主进程与服务 | `#1baf7a` | `#199e70` |
  | 后台 | `#eda100` | `#c98500` |
  | 启动的程序 | `#e87ba4` | `#d55181` |

  卡顿柱与慢交互使用保留的状态色（`#ec835a`、`#d03b3b`），并且始终配有图例文字。状态色只用于结论、卡顿和侧栏圆点；文字从不使用数据色。
- **标记**：
  - 堆叠面积为淡填充，每个组成部分顶边画一条 1.5px 的线；组成部分为零的地方不画线。
  - 网格线为实线细线；只有 200 毫秒阈值线用虚线，并直接标出「200 毫秒」。
  - 刻度文字画在数据上层，带一圈底色描边，曲线穿过时也看得清。
  - 悬停标记 ≥ 7px，带 2px 底色描边。
- **提示框**：一个提示框列出所有组成部分，数值在前、名称在后，每行用一小段对应颜色的线作为色键。
- **滚动条**：页面和抽屉统一为 DSH 配色的细滚动条：没有轨道、箭头和角块，圆角滑块在指向、拖动时加深。两侧都预留滚动条宽度的留白，内容保持居中，切换到长短不同的内容时也不会左右移动。
- **动效**：
  - 没有任何循环动画；
  - 每次读数到达时，状态点和最新数据点各闪一下；
  - 抽屉滑入 0.34 秒，切换对象时内容淡入；
  - 减少动态效果模式下全部改为即时完成。

## 交互约定

- 悬停或键盘查看趋势时，时间窗口固定，查看的时刻不会滑走。停在没有读数的空档时，提示框不借用相邻的读数。
- 指向任一组成部分（图例、表格行），趋势图里只突出它；高亮通过根节点上的样式实现，图表不会因此重新渲染。
- 表格每次读数都会按所选列重新排序；鼠标停在表上时行序保持，新出现的行排在末尾。
- 表格里，行左侧的箭头只负责展开，点行的其余部分打开详情，两件事不会互相误触。
- 抽屉：
  - 从页面打开时总是重新开始；从抽屉里打开时进入下一层，左上角返回上一层；
  - 上下箭头（K / J）按表格此刻显示的顺序切换，收起的行不在其中；
  - Esc 或点遮罩关闭，焦点回到打开它的元素。
- 窄屏：
  - 880px 以下，表格去掉趋势小图列，轨道左栏收窄；
  - 600px 以下，抽屉占满整页，表格只留名称、CPU、内存，说明改为指向名称时显示，列头不再写口径。
